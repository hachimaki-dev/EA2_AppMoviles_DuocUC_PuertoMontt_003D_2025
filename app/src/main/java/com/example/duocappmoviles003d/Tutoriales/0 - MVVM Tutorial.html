🎯 ¿Qué es MVVM?

MVVM es un patrón de arquitectura que nos ayuda a organizar mejor nuestro código en aplicaciones Android.

🍕 Analogía: El Restaurante

👨‍🍳

Model (Modelo)

La cocina y los ingredientes. Los datos puros de tu app.

SignUpUiState - Los datos del formulario
🧑‍💼

ViewModel

El mesero. Conecta la cocina con el cliente y maneja los pedidos.

SignUpViewModel - La lógica del registro
👤

View (Vista)

El cliente. Solo ve el menú y hace su pedido.

RegisterScreen - La interfaz visual

✨ ¿Por qué usar MVVM?

  • ✓ Separación clara: La vista no sabe cómo funcionan los datos, solo los muestra.
  • ✓ Fácil de testear: Puedes probar la lógica sin necesidad de la interfaz.
  • ✓ Reusable: Puedes cambiar la vista sin tocar la lógica.
  • ✓ Mantenible: Cada parte tiene su responsabilidad específica.

🧩 ViewModel en Android

En Android, un ViewModel es una clase especial que guarda y maneja los datos de tu interfaz de usuario.

🎒 ¿Qué hace un ViewModel?

✅ Responsabilidades

  • • Almacena el estado de la pantalla
  • • Procesa la lógica de negocio
  • • Valida los datos del usuario
  • • Se comunica con repositorios/APIs
  • • Expone datos a la vista de forma observable

❌ NO hace

  • • NO contiene referencias a vistas (UI)
  • • NO maneja colores, tamaños o estilos
  • • NO muestra Toast o Snackbars directamente
  • • NO depende del Context de Android

📦 Estructura básica

// Heredamos de ViewModel de Android
class SignUpViewModel : ViewModel() {

    // Estado privado (solo el ViewModel lo modifica)
    private val _uiState = mutableStateOf(SignUpUiState())

    // Estado público (solo lectura para la vista)
    val uiState: State = _uiState

    // Funciones para modificar el estado
    fun onNameChange(value: String) {
        _uiState.value = _uiState.value.copy(name = value)
    }
}

💡 Punto clave: El ViewModel es como un "asistente inteligente" que mantiene los datos organizados y actualizados, incluso si giras el teléfono.

🔗 Conectando Vista y ViewModel

Ahora veremos cómo RegisterScreen (la vista) se comunica con SignUpViewModel.

🎬 Paso 1: Crear el ViewModel en MainActivity

class MainActivity : ComponentActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        enableEdgeToEdge()
        setContent {
            // Creamos una instancia del ViewModel
            RegisterScreen(viewModel = SignUpViewModel())
        }
    }
}

⚠️ Nota: En apps más avanzadas, usarías viewModel() de Compose para que Android gestione automáticamente el ciclo de vida. Por ahora, crearlo manualmente está bien.

🎨 Paso 2: Recibir el ViewModel en el Composable

@Composable
fun RegisterScreen(viewModel: SignUpViewModel) {
    // Obtenemos el estado actual del ViewModel
    val state = viewModel.uiState.value

    // Ahora podemos usar 'state.name', 'state.email', etc.
}

📝 Paso 3: Mostrar y modificar el estado

👁️ Leer el estado (Vista → ViewModel)

OutlinedTextField(
    value = state.name, // Leemos del estado
    onValueChange = { /* ... */ },
    label = { Text("Nombre") }
)

✏️ Modificar el estado (Vista → ViewModel)

OutlinedTextField(
    value = state.name,
    onValueChange = { nuevoNombre ->
        viewModel.onNameChange(nuevoNombre)
    },
    label = { Text("Nombre") }
)

🔄 Flujo completo de datos

  1. 1
    Usuario escribe en el campo: Ej: "Carlos"
  2. 2
    Se ejecuta onValueChange: viewModel.onNameChange("Carlos")
  3. 3
    ViewModel actualiza el estado: _uiState.value = _uiState.value.copy(name = "Carlos")
  4. 4
    Compose detecta el cambio: La vista se redibuja automáticamente mostrando "Carlos"

💚 Ventaja: La vista nunca modifica directamente el estado. Siempre pasa por el ViewModel, quien decide qué hacer con los datos (validar, transformar, etc.).

💾 Estados: mutableStateOf vs State

En Compose, los estados son variables especiales que actualizan la interfaz automáticamente cuando cambian.

🔍 Diferencia clave

📝 mutableStateOf

Variable que puede cambiar (lectura y escritura)

// Privado: solo el ViewModel lo modifica
private val _uiState =
    mutableStateOf(SignUpUiState())

// Podemos hacer:
_uiState.value = nuevoEstado ✅
Analogía: Un cuaderno donde TÚ escribes

👁️ State

Variable de solo lectura (solo ver, no modificar)

// Público: la vista solo lee
val uiState: State =
    _uiState

// Solo podemos hacer:
val nombre = uiState.value.name ✅
uiState.value = nuevoEstado ❌
Analogía: Un libro que solo puedes LEER

🎭 ¿Por qué dos variables?

🔒
Encapsulamiento:

La vista NO puede modificar directamente _uiState. Solo puede leer uiState y llamar funciones del ViewModel.

🛡️
Control total:

El ViewModel controla CUÁNDO y CÓMO se actualiza el estado. Puede validar, formatear, etc.

🐛
Menos bugs:

Si algo sale mal con los datos, sabes que el problema está en el ViewModel, no en la vista.

📚 data class y copy()

// SignUpUiState es un "data class"
data class SignUpUiState(
    val name: String = "",
    val email: String = "",
    val password: String = ""
)

// Para modificar UN campo sin tocar los demás, usamos copy()
fun onNameChange(value: String) {
    _uiState.value = _uiState.value.copy(name = value)
    // Crea una COPIA con 'name' nuevo, pero email y password iguales
}

🔑 Concepto importante: data class nos da automáticamente la función copy(), que crea una nueva instancia cambiando solo lo que especifiquemos.

⚙️ Código Línea por Línea

📄 SignUpUiState (El Modelo)

// data class: genera automáticamente copy(), equals(), toString()
data class SignUpUiState(
    val name: String = "",      // Valor por defecto: texto vacío
    val email: String = "",     // Si no se pasa nada, será ""
    val password: String = "",  // Los valores por defecto evitan errores
    val errorMessage: String? = "" // String? significa que puede ser null
)

💡 ¿Qué es esto?

Es una clase que representa todos los datos que necesita la pantalla de registro. Es como un "contenedor" con cajitas para cada dato. La palabra data le dice a Kotlin que genere funciones útiles automáticamente.

🧩 SignUpViewModel (La Lógica)

// Heredamos de ViewModel (clase de Android)
class SignUpViewModel : ViewModel() {

    // 1️⃣ Estado PRIVADO (solo este ViewModel puede modificarlo)
    private val _uiState = mutableStateOf(SignUpUiState())
    // mutableStateOf() crea un estado observable
    // Inicialmente está vacío: name="", email="", password=""

    // 2️⃣ Estado PÚBLICO (la vista solo puede leerlo)
    val uiState: State = _uiState
    // Exponemos el estado pero como "solo lectura"

    // 3️⃣ Función para actualizar el nombre
    fun onNameChange(value: String) {
        // copy() crea una COPIA del estado actual
        // cambiando SOLO el campo 'name'
        _uiState.value = _uiState.value.copy(name = value)
    }

    // 4️⃣ Función para actualizar el email
    fun onEmailChange(value: String){
        _uiState.value = _uiState.value.copy(email = value)
    }

    // 5️⃣ Función para actualizar la contraseña
    fun onPasswordChange(value: String){
        _uiState.value = _uiState.value.copy(password = value)
    }
}

✅ Patrón correcto

// La vista llama a la función
viewModel.onNameChange("Carlos")

// El ViewModel actualiza el estado
_uiState.value =
  _uiState.value.copy(name = "Carlos")

❌ Incorrecto

// ¡La vista NO debe hacer esto!
viewModel.uiState.value.name = "Carlos"
// ❌ No compila: uiState es solo lectura

viewModel._uiState.value = ...
// ❌ No compila: _uiState es privado

📱 RegisterScreen (La Vista)

@Composable
fun RegisterScreen(viewModel: SignUpViewModel) {
    // Obtenemos el estado actual
    val state = viewModel.uiState.value

    // ... código de UI ...

    OutlinedTextField(
        value = state.name, // 👁️ LEEMOS del estado
        onValueChange = { nuevoTexto ->
            viewModel.onNameChange(nuevoTexto) // ✏️ ACTUALIZAMOS vía ViewModel
        },
        label = { Text("Nombre") }
    )

    OutlinedTextField(
        value = state.email, // 👁️ LEEMOS
        onValueChange = { viewModel.onEmailChange(it) }, // ✏️ ACTUALIZAMOS
        label = { Text("Email") }
    )

    OutlinedTextField(
        value = state.password, // 👁️ LEEMOS
        onValueChange = { viewModel.onPasswordChange(it) }, // ✏️ ACTUALIZAMOS
        label = { Text("Contraseña") },
        visualTransformation = PasswordVisualTransformation()
    )
}

🎯 Resumen del flujo

  1. 1. Usuario escribe → onValueChange se ejecuta
  2. 2. Vista llama → viewModel.onNameChange("texto")
  3. 3. ViewModel actualiza → _uiState.value = _uiState.value.copy(name = "texto")
  4. 4. Compose detecta cambio → La UI se redibuja automáticamente con el nuevo valor

✏️ Ejercicio 1: Validación de Email

🎯 Objetivo

Agregar validación para verificar que el email tenga formato correcto (contenga "@").

📝 Pasos sugeridos:

  1. Agregar un campo isEmailValid: Boolean en SignUpUiState
  2. Modificar onEmailChange() para validar si el email contiene "@"
  3. Actualizar el estado con copy(email = value, isEmailValid = ...)
  4. En la vista, mostrar un error si state.isEmailValid == false
💡 Ver pista 
// En SignUpUiState
data class SignUpUiState(
    val name: String = "",
    val email: String = "",
    val password: String = "",
    val isEmailValid: Boolean = true, // Agregar esto
    val errorMessage: String? = ""
)

// En SignUpViewModel
fun onEmailChange(value: String) {
    val esValido = value.contains("@") && value.length > 3
    _uiState.value = _uiState.value.copy(
        email = value,
        isEmailValid = esValido
    )
}

✏️ Ejercicio 2: Validación de Contraseña

🎯 Objetivo

Validar que la contraseña tenga al menos 6 caracteres.

📝 Pasos sugeridos:

  1. Agregar isPasswordValid: Boolean en SignUpUiState
  2. En onPasswordChange(), validar value.length >= 6
  3. Mostrar mensaje de error en la vista si no es válida
💡 Ver solución completa 
// SignUpUiState actualizado
data class SignUpUiState(
    val name: String = "",
    val email: String = "",
    val password: String = "",
    val isEmailValid: Boolean = true,
    val isPasswordValid: Boolean = true, // Nuevo campo
    val errorMessage: String? = ""
)

// En el ViewModel
fun onPasswordChange(value: String) {
    val esValida = value.length >= 6
    _uiState.value = _uiState.value.copy(
        password = value,
        isPasswordValid = esValida
    )
}

// En la vista
OutlinedTextField(
    value = state.password,
    onValueChange = { viewModel.onPasswordChange(it) },
    label = { Text("Contraseña") },
    isError = !state.isPasswordValid,
    supportingText = {
        if (!state.isPasswordValid) {
            Text("Mínimo 6 caracteres", color = Color.Red)
        }
    }
)

✏️ Ejercicio 3: Función para Registrar

🎯 Objetivo

Crear una función onRegisterClick() que valide todos los campos antes de "registrar".

📝 Pasos sugeridos:

  1. Crear función fun onRegisterClick() en el ViewModel
  2. Verificar que ningún campo esté vacío
  3. Verificar que email y password sean válidos
  4. Si todo está bien, actualizar errorMessage a "¡Registro exitoso!"
  5. Si algo está mal, mostrar mensaje de error específico
💡 Ver ejemplo de implementación 
fun onRegisterClick() {
    val currentState = _uiState.value

    when {
        currentState.name.isBlank() -> {
            _uiState.value = currentState.copy(
                errorMessage = "El nombre no puede estar vacío"
            )
        }
        !currentState.isEmailValid || currentState.email.isBlank() -> {
            _uiState.value = currentState.copy(
                errorMessage = "Email inválido"
            )
        }
        !currentState.isPasswordValid -> {
            _uiState.value = currentState.copy(
                errorMessage = "Contraseña muy corta"
            )
        }
        else -> {
            // ¡Todo válido! Aquí llamarías a tu API
            _uiState.value = currentState.copy(
                errorMessage = "✅ ¡Registro exitoso!"
            )
        }
    }
}

🌟 Ejercicio Bonus: Loading State

🎯 Objetivo Avanzado

Agregar un estado de "cargando" mientras se procesa el registro (simulado).

📝 Ideas:

  • Agregar isLoading: Boolean = false en SignUpUiState
  • Al hacer clic en "Registrarse", cambiar isLoading = true
  • Simular un delay con delay(2000) (necesitas hacer la función suspend)
  • Después del delay, cambiar isLoading = false y mostrar resultado
  • Deshabilitar el botón mientras isLoading == true
